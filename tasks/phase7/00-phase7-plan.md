# Phase 7 — Frontend Completion on AQABA AQUA AI

**Project:** AQABA AQUA AI (formerly ReefShield Aqaba — the rename landed 8 Aug 2026)
**Written:** 8 August 2026
**Window:** 8 Aug → 13 Aug 2026, the last five days before presenting.

Phase 6 measured the system and found the same shape in every row: **the backend is
real and the screen is missing.** Six rows passed on their backend half with the
frontend half open. Thirty rows were never tested at all. One row failed outright.

Phase 7 closes that gap and nothing else. Every feature this repo has ever claimed
gets a real surface, on the new brand, wired to the real endpoint, or it gets written
down as not built. There is no third outcome.

## What already landed on 8 Aug, before this phase starts

Read this section before you write a line of code. Building any of it again is
wasted time, and building *around* it is how two design systems end up in one app.

- **The brand is done and machine-enforced.** Tokens are generated by
  `scripts/qa_frontend_palette.py` and validated for WCAG AA and colour-blind
  separation. `scripts/qa_frontend_tokens.py` **fails the build on a hex literal**
  anywhere in `frontend/src/`. You do not pick colours in this phase. See
  [`00-design-system.md`](00-design-system.md).
- **The router is real.** 18 routes, `/` is the marketing home, `/dashboard` is the
  map. Hand-rolled in `frontend/src/app/useRoute.ts` — no react-router, on purpose.
- **The shell exists**: `DashboardChrome` (navy rail), `PageShell`/`Section`/`Card`,
  `Logo`, `Link`, `Segmented`.
- **Every page has a file and renders.** A smoke spec walks all 18 routes and
  asserts no console error and **no untranslated i18n key in either language**.
- **`frontend/src/api/live.ts` already wraps the whole real API surface** — events,
  reef zones, mooring, data sources, models, forecast, ask, reports, sites, photos.
  If you need an endpoint, look there before writing a fetch.
- **i18n is four namespaces** — `common`, `nav`, `pages`, `tools` — currently **736
  keys, EN/AR at exact parity**.

**What this phase inherits is a skeleton with real data in some limbs.** The pages
exist; most of them are thin. Making them complete, correct and beautiful is the work.

## Standing law for this phase

1. **No hex literals, no ad-hoc colour, no second design system.** Everything comes
   from the tokens. `python3 scripts/qa_frontend_tokens.py` must exit 0 before you
   push. If you genuinely need a raw value (fixed brand artwork only), append
   `// token-ok: <reason>` on the same line — and expect to justify it in review.
2. **A number on screen comes from the API or it does not go on screen.** No
   hardcoded `78%`, no `AP 0.5923` typed into JSX, no invented reef name. If the
   endpoint cannot supply it, render the honest empty state instead. The foundation
   preview deck is full of placeholder numbers — **it is a design reference, not a
   data reference.**
3. **Missing is never zero.** A null renders as a visible gap through
   `ValueWithUnit`, never as `0`, never as an em dash that looks like a value.
   Phase 6 found `/alerts` returning `[]` legitimately; "no zone was reached" and
   "a zone was reached with negligible effect" are different sentences.
4. **Every caveat the API sends must render.** The backend already ships structured
   `caveats[]` on most responses. Dropping them in the UI is the single easiest way
   to turn an honest system into a dishonest one, and it is invisible in review.
5. **Bilingual is not a pass at the end.** Add both EN and AR keys in the same commit
   as the component. `scripts/qa_frontend_rtl.py` and the parity check must stay
   green. Arabic is a first-class language in this product, not a toggle.
6. **Accessibility is a build gate, not an aspiration.** `hardening.spec.ts` runs axe
   over four theme × language combinations. A contrast regression fails the build.
   `--ink-3` is for text on `--canvas` and `--surface` only — never on `--surface-2`.
7. **You may not mark a row Done without a screenshot.** Same discipline as Phase 6
   evidence: a claim with no artifact is a claim, not a result.
8. **If a feature has no backend, say so on the screen.** Do not build a beautiful
   shell that implies data behind it. `b1`, `b2`, `b3` and `b9` have no backend at
   all — they are not "coming soon" cards, they are absent, and the Honest Limits
   page is where absent things are named.

## The definition of done, per feature

A feature is Done when **all six** are true. Five out of six is not done.

| # | Gate | How it is checked |
|---|---|---|
| 1 | It has a home | A named route in `useRoute.ts`, reachable from the nav rail or an in-page link — not orphaned |
| 2 | It renders real data | Devtools Network shows the call; the number on screen matches the response body |
| 3 | It handles its three states | loading, empty-but-legitimate, and unreachable — each visually distinct and each explaining itself |
| 4 | It carries its caveats | Every `caveats[]` entry and every `*_status` placeholder flag is visible, not swallowed |
| 5 | It works in Arabic | RTL mirrored, numerals LTR-isolated, both locales at key parity |
| 6 | It passes the gates | `npm run qa`, axe clean, `qa_frontend_tokens.py` + `qa_frontend_rtl.py` exit 0, screenshot filed |

## The five things most likely to go wrong

Each of these has already cost this project real time once. They are listed here so
Phase 7 does not pay for them twice.

1. **Building against the foundation deck's numbers.** `frontend/Foundation pages
   built/` is a design-canvas prototype. Its `78%`, its `AP 0.5923`, its "Wadi Kamar"
   ranking and its `07:40:41` countdown are **hand-typed placeholders**. Copy the
   layout; never copy the value.
2. **Assuming an endpoint exists because a planning doc names it.** Three frontend
   comments were stale for weeks, claiming `/api/v1/reef-zones` and
   `/api/v1/runoff/predict` did not exist. Both did. Check `live.ts` and, if it is
   not there, `curl` the running API before you conclude anything.
3. **`VITE_DATA_SOURCE=http` exposing untested paths.** The app defaults to
   `fixtures`. The HTTP client had two real bugs that had never run — one blanked the
   whole dashboard on 8 Aug. **Test your screen in both modes**, because the demo may
   run in either.
4. **Breaking the `data-*` test contract while restyling.** Seven Playwright specs
   target `[data-chrome]`, `[data-mode=…]`, `[data-open-overlay=…]`, `[data-risk-card]`,
   `[data-band]`, `[data-time-handle]`, and named map layer IDs. Restyle freely;
   **rename nothing**.
5. **Silently refreshing generated fixtures.** Running
   `scripts/frontend_panels.py` regenerates `public/fixtures/` from `docs/` — and will
   pull in unrelated doc drift with it. On 8 Aug that changed the limitations count
   from 9 to 12 and broke two specs. If you regenerate, **own the diff and update the
   specs deliberately**, or do not regenerate at all.

## Exit criteria for the phase

The phase is over when all of the following are true at once, verified on the real
running stack, not asserted:

- Every one of the 44 rows in [`00-feature-surface-matrix.md`](00-feature-surface-matrix.md)
  reads **Done**, or **Absent — stated on Honest Limits** with the sentence that
  states it quoted in the matrix.
- `npm run qa` green; `npx playwright test` green except the documented environmental
  failures, each named in the matrix with a reason.
- `qa_frontend_tokens.py`, `qa_frontend_docs.py`, `qa_frontend_rtl.py`,
  `qa_frontend_freeze.py` all exit 0.
- `grep -ril "reefshield" frontend/` returns nothing.
- The app runs with **wifi physically off** and the map, the rail and Arabic labels
  still render — checked by a person, not only by the DNS-blackhole spec.
- A screenshot of every route exists under `tasks/phase7/evidence/<route>/`, in both
  languages, in both themes.
