This is the exact "works on my machine" trap this phase's two-tester rule exists to
catch: the endpoint's correctness is currently accidental, contingent on which
teammate's git-ignored local cache happens to be populated, not on the code being
correct. The real bug (already precisely named in Karam's note in `03-nizar.md`)
is that `currents_agreement()` in `main.py` (~line 787) guards `hycom_path.exists()`
with a clean 503 but has no equivalent guard for `copernicus_path` before
`compare_hycom_vs_copernicus()` opens it -- so the endpoint's reliability depends on
an un-committed file being present, with no defensive check and no honest degradation
when it isn't. Not fixed here, per this phase's rule 1 (Copernicus Marine credentials
DO exist in `backend/.env` now, which would make fetching the missing cache possible,
but doing that mid-Phase-6 would be implementing the fix, not testing). Left named for
Phase 7: either (a) fetch/commit-a-fallback for the Copernicus Marine historical cache,
or (b) add the same exists-or-503 guard that already exists for the HYCOM path.
